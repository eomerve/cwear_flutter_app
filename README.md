# C-Wear — Flutter mobile app

A responsive Android/iOS Flutter implementation of the **four supplied PDF screen designs**:

| Bottom tab | Flutter screen | Supplied reference |
| --- | --- | --- |
| Connect | `ConnectScreen` | `Connect sensor.pdf` |
| Live | `LiveScreen` | `Live monitoring.pdf` |
| History | `HistoryScreen` | `Respiratory history.pdf` |
| Profile | `ProfileScreen` | `Edit profile.pdf` |

The PDF-provided sensor photo and avatar are extracted into `assets/images/` to better match the original look. UI colors, typography, bottom navigation, and card placements reflect the reference layouts and scale to different mobile screen widths.

## Behaviors

- **Real QR scanner**: camera preview and QR recognition with `mobile_scanner` (CameraX / Apple Vision). Flashlight toggle included. Accepts any nonempty QR for the demo, no Bluetooth, no network pairing, no backend.
- **Manual code option**: activates the same demo workflow when camera access is unavailable or while using a simulator.
- **Before activation**: live BPM, chart, status, historical summaries and bars occupy their normal layout but are partially transparent and **contain no readings**. The empty chart retains labels and grid.
- **After activation**: automatically opens Live, marks **Aera Band · Connected** with a **DEMO** label, displays 16 breaths/min (within the commonly used resting adult range of 12–20 BPM), and animates a smooth synthetic 15-second respiratory waveform. History shows clearly labeled illustrative example data. No real physiological data is captured.
- **Disconnect**: Connect tab > **Disconnect demo sensor** returns Live/History to their empty disabled states.
- **Profile**: edit full name (required), age (integer from 1 to 120), and portrait via the device photo library. Save and top-left back arrow both **save then return to Live**. Cancel returns to Live without saving. Bottom navigation from an edited profile saves valid changes before switching.
- **Persistence**: `SharedPreferencesAsync` stores name, age, and the demo connection flag. Raw QR content is not retained. Profile photo is copied to the application's document directory and its path is stored in preferences. No database required.
- **History periods**: Day / Week / Month segmented control, previous/next periods, and week day picker. The illustrative chart is only shown for the current period while the demo is connected.

> **Important:** The breathing values, history, connection badge and status are simulations for UI testing, not a connection to medical hardware and not clinical/diagnostic information.

## Technology versions

- Flutter **3.35 or newer** with Dart **3.9 or newer** (stable preferred)
- Android **minSdk 24**, Android compile SDK provided by the installed current Flutter SDK
- iOS deployment target **15.0** (macOS, Xcode and CocoaPods required)
- `mobile_scanner: 7.4.4` — selected for its Android start/dispose crash fixes
- `shared_preferences: 2.5.4` — persistence with `SharedPreferencesAsync`
- `image_picker: 1.2.1` — choose image from device gallery
- `path_provider: 2.1.5` — persistent local profile image
- No Firebase, Supabase, BLE library, graph plugin, Expo or Node.js dependencies

These direct dependency versions are **fixed** rather than unconstrained to reduce unexpected major-version updates. Flutter's native Android/iOS shell is deliberately generated by the Flutter version **installed on your computer**, avoiding stale Gradle/Xcode project templates.

## Windows / Android instructions

1. Install [Flutter SDK](https://docs.flutter.dev/get-started/install), Android Studio/SDK, **JDK 17**, and add Flutter to your `PATH`.
2. Unzip this folder to a short, ASCII-only folder path such as `C:\dev\CWear_Flutter`.
3. Open **PowerShell** in that folder:

   ```powershell
   flutter doctor -v
   Set-ExecutionPolicy -Scope Process Bypass
   .\setup.ps1
   flutter devices
   flutter run
   ```

4. Use a physical Android device (USB debugging enabled) for reliable QR camera access. A sample QR is included at `demo_qr/CWear_Demo_Sensor_QR.png` (display it on another screen or print it). On an emulator, the **Enter sensor code manually** button also exercises the complete simulated connection flow.
5. For a release build after configuring Android signing:

   ```powershell
   flutter build apk --release
   ```

   APK output: `build/app/outputs/flutter-apk/app-release.apk`.

The Windows `setup.ps1` script generates the Android runner with `flutter create --platforms=android .`, applies camera/photo permissions and Android `minSdk 24`, removes Flutter’s unrelated default counter-app test, and runs `flutter pub get`. **Only run setup once** (or again if native folders need regeneration). Do not use `flutter create --overwrite` unless you mean to replace generated platform files.

## macOS / iOS instructions

1. Install Flutter 3.35+, Xcode, Xcode command-line tools and CocoaPods; run `flutter doctor -v`.
2. In the extracted project directory:

   ```bash
   ./setup.sh
   flutter devices
   flutter run
   ```

3. In Xcode, configure **Signing & Capabilities** for the `ios/Runner.xcworkspace` project using your Apple Developer team. For distribution, use `flutter build ipa` with appropriate signing.
4. Camera scanning is best tested on a **physical iPhone**; the iOS simulator does not provide an equivalent real-world QR-camera experience.

If a project was first set up on Windows and moved to a Mac, `./setup.sh` will generate the iOS runner. Alternatively, run `flutter create --platforms=ios .` followed by `dart tool/configure_platforms.dart` on macOS. Do not add native camera/photo permissions by hand; the configuration tool does this.

## Common troubleshooting

- **Flutter command not found**: fix your Flutter SDK installation and PATH; this is not an Expo project and does not need Node/npm.
- **Android Gradle/JDK error**: use JDK 17 with Android Studio and the Gradle wrapper generated by your installed Flutter SDK; do not insert an arbitrary Gradle/AGP version.
- **Camera black / permissions denied**: uninstall/reinstall after `setup`, grant camera access in Android/iOS Settings, test on physical device, and confirm no other app holds the camera.
- **Image selection not working**: permit photo library access in device Settings. The app requests access only when changing the portrait.
- **iOS signing error**: choose your Apple team, set a unique bundle identifier in Xcode, and use a physical iPhone with a trusted developer certificate.
- **No respiration after opening the app**: this is expected. Go to **Connect** and scan any QR code (or use manual entry).
- **No Flutter SDK on this development machine**: the native runners must be generated from the local installed Flutter SDK. No APK/IPA is bundled in this source archive.

## Privacy and medical disclaimer

Data is stored locally; QR payloads are not retained and are accepted without authentication solely to trigger a **simulated** connected state. **Do not use this application for patient care, respiration assessment or diagnosis.** To connect a real sensor, hardware integration, data validation, security, regulatory verification and appropriate clinical safety testing must be added separately.
